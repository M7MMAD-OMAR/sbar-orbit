# Changelog

Versions follow Semantic Versioning. Alpha releases are experimental and may change interfaces without compatibility guarantees.

## 0.1.0-alpha.4 - 13 September 2026

- The package that goes to the registry is built by a different path than the source archive, and nothing tested it. `bun pm pack` reads the working tree while the archive is built from the git index, so a directory named in `files` shipped whatever happened to be sitting in it: `0.1.0-alpha.3` carries six `__pycache__` files that were never meant to leave this machine. They are dead weight rather than a leak, since a `.pyc` records its source by relative path and is recompiled the moment the timestamps disagree, which they do after an extract. Two more of the same kind were found with it: `bun.lock` was not shipped at all, so `install --reinstall-deps` could not resolve against the frozen lockfile its own help names, and `install --native` spawned a bootstrap the package does not carry, so it failed with a path bash could not open instead of with a reason. The native step now refuses by name, `native-bootstrap-absent`, and points at the repository rather than at a command an agent may run. `tests/packaging.test.ts` packs the repository and fails on any shipped path git does not track, which is the general form of the `__pycache__` case rather than a list of the three files found today. Both checks were run against the unfixed code first: the tarball listed ten untracked entries, and the refusal read `bash: .../bootstrap.sh: No such file or directory`. Measured from an extracted tarball on this host on 13 September 2026: the frozen lockfile installs 100 packages in 319 ms, and `install --native --dry-run --json` reports the native step failed with the new reason. The published `0.1.0-alpha.3` still carries all three, since a published version is immutable; the next version is where this lands.
- The publication audit read a systemd template unit as an email address, so `user@1000.service` was a finding and the pre-commit hook refused any file that wrote down the unit this project's own installer starts. A rule that cannot name its own service stops the documentation rather than a leak. Unit names are now skipped by their suffix, and an address in the same file is still caught.
- Gate 3 is closed, on a container that is a machine rather than a filesystem. `experiments/fresh-machine/systemd-session.sh` gives a clean Fedora 44 image the half the existing one cannot have: systemd as PID 1, a lingering unprivileged account whose user manager owns delegated `cpu`, `memory` and `pids` controllers, and therefore a real `sbarorbit.slice`. On that machine, from tracked source and the frozen lockfile, the dependency install completes, `preflight` passes, the bootstrap builds the private compositor and the pointer helper, `./install.sh` runs to completion with every step `done`, the broker service comes up and answers `doctor`, a browser session opens, and a native session launches an X11 application, accepts typed text and returns a 1280 by 800 JPEG of it. 1549 ms of processor for the session steps inside 4 CPU, 7946 MiB and 1536 tasks, zero refused forks, and the frame is kept beside the log. Two limits are printed beside it rather than left out: there is no GPU, no compositor and no screen, and the container reads the host's processor and memory totals, so the budget it sized is a quarter of the host. That is `Limited`, not `Measured`. The same script against the commit before the fixes reproduces both failures it found.
- Orbit could not create a session at all on a machine without `btrfs-progs`, and said nothing about why. `Bun.spawn` throws on a binary that is not there rather than returning a failing exit code, so the absence of the tool was not a false out of `createSubvolume`, which is what every caller was written for, but an exception through all of them. Measured 13 September 2026 on a fresh Fedora machine: every `session.create` failed with `ENOENT: posix_spawn \'/usr/bin/btrfs\'`, browser and native alike, on a filesystem that was never going to hold a restore point. A machine with no btrfs now loses restore points and keeps its sessions.
- An unexpected exception in the broker was unattributable, which is what made the above take a day to see rather than a minute. The metadata journal records that a method failed and its code, never the exception, and the line that used to put the cause on the broker's own stderr went with the journal that replaced it, so the message existed nowhere: not in the client response, which is fixed text by design, not in the journal, not in `diagnostics --report`, not on stderr. The cause is on stderr again, beside its trace ID, for exceptions that are not Orbit's own. That is the operator's journal, not anything an agent or a page can read, and the raw text still never reaches a client.
- Split the desktop panel into the three things it was doing in one 2156 line file. `desktop/panel_broker.py` is everything that speaks to Orbit, with no GTK in it: the HTTP over the broker's Unix socket, the status shape the mark renders from, the command socket by which a second invocation hands its request to the first, and the two helpers that shell out. `desktop/panel_draw.py` is the geometry and the paint, the easing curves, the capsule and card outline and the neck between them, and the two widgets that carry them. `desktop/panel.py` keeps the application: the window, where it sits, what it does when the person touches it, and the settings window. Behaviour is unchanged and the content is the same code, moved.
- The half of the panel that talks to Orbit has tests for the first time, in `tests/panel-broker.test.ts`, which is what the split was for: none of it could be reached without a display before. Four checks cover presence being fetched only when something will read it, a second panel handing its request over instead of drawing a second mark, a stale socket from a killed panel being taken over rather than deferred to, and the viewer link being opened only when it carries the loopback address and a token. Verified in a private Orbit display rather than on the person's screen: the mark draws at the edge, hovering pulls the card out on its neck, and `--settings` reaches the running panel through the command socket and opens the window.
- Wrote down what the diagnostic journal costs the person debugging Orbit, which is where the click above spent a day. A `BACKEND_ERROR` reaches its caller as the fixed words `Request failed` and is recorded as a code with no message, so the backend's own sentence survives nowhere: not in the reply, not on disk, and not in the broker's stderr, which stopped carrying it when the journal arrived. Letting the message through is not an option, because a Playwright error quotes the selector it was given and a navigation error quotes the URL, which is page content by another name. So [diagnostics](docs/diagnostics.md) names the route to a cause instead: reproduce against `BrowserBackend` in process, outside the wrapper, which is how `click: Target page, context or browser has been closed` was finally read, and use the trace ID to tie that reproduction back to the recorded event.
- A click that closes its own tab is no longer a backend error. Clicking a popup's Close button, or anything else with `window.close()` behind it, made Playwright reject the gesture that caused the close, because the target it was driving went away mid click, and the agent saw `BACKEND_ERROR` for an action that did exactly what it was asked. Measured on this host before the fix, twenty clicks on a popup that closes itself: three rejections, every one of them `click: Target page, context or browser has been closed`. That is why it had been read as a flaky test rather than a defect. Forgiveness needs two conditions and not one: the page must be gone, and the session must still have a tab to go back to. The second was found by the concurrency test rather than by reasoning, since stopping a session closes every page as well, and a first version that asked only whether the page had closed reported a cancelled action as a successful one. Every other click failure is still raised, because a selector that matches nothing must not read as success, and a closed page is recognised by `isClosed` rather than by matching the message. The reply carries `closed: true` beside `applied: true`, since whether the tab survived is the part Orbit can see and whether the page acted on the gesture never was. The same twenty clicks now fail none, and the full suite is 203 passing. The test is deterministic rather than a repeat of the race: the tab goes while the click is still waiting for its target to become clickable, which reaches the same code path every time, and it was run first against the unfixed backend, where it failed with the code it was written to remove.
- One colour now means one thing. Working was green on the desktop mark and blue on the agent pointer, so the same fact wore two colours depending on where a person happened to look. Working is `#255fce` everywhere it appears: the mark, the pointer, and the wash at the screen edges, whose default stops being the desktop's accent, since a wash laid over a wallpaper nobody chose cannot borrow its contrast from a palette. The word `accent` in `frameColor` still asks for the desktop's own colour, and any value still overrides both. The brand stays the navy `#204c87` and the gap between the two blues is now a rule with a check behind it in [brand](docs/brand.md), because closing it would leave the mark looking lit whenever it is drawn. The glow also got deeper, 28 pixels to 120, with its stops bunched against the edge and thinned out over the rest: a shallow wash can only be seen by being dense, and dense against an edge is a border. Four strips at that depth are about 3.8 MiB of buffer between them on a 2560 by 1440 output, against tens of megabytes for one surface covering the output with a transparent middle. Six checks in `tests/settings.test.ts` pass. Not measured: what the deeper strips cost to paint against the 28 pixel ones, which is the measurement [desktop presence](docs/desktop-presence.md) records for the pulse and not for the depth.
- The viewer gave the screen back the room it was spending on its own controls. The picture's height is now measured from the window and the things above it rather than left to the flow, a `ResizeObserver` on the header, the stage bar, the tab row and the panels recomputes it, and the canvas keeps the captured aspect ratio, so nothing is stretched to fill what is left. Everything secondary went into native disclosures under the stage: display settings, the problem report, typing, and ending the session. The sidebar collapses from a button in the header and remembers the choice in local storage where the browser allows it, starts closed at 900 pixels and under where it opens as an overlay, and closes on Escape. **Focus view** replaces "Make it bigger" and keeps the conversation, the project and the page tabs while it hides the rest; **Fullscreen** uses the browser's own API and enters focus view with it, and says what to use instead when a browser refuses it. None of these touch the session, which is still the difference between them and **Screen size**. What a person is looking at is now named in the browser's own tab as `Conversation · Project | Orbit`, and a conversation strip above the stage stays usable with the sidebar closed. Taking over opens the typing disclosure rather than leaving a person to find it.
- **Report a problem** in the viewer prepares the diagnostic report, and nothing leaves the machine until the person chooses. The panel prepares on demand, opens itself when a viewer error occurs, and while the viewer is open it checks for new agent-tool errors every 15 seconds with preparation limited to once every 30. **Download report** saves the whole retained history as JSON. **Continue to GitHub** opens this project's new-issue page with a title and a compact summary already filled in, capped at 7,000 URL characters by dropping events until it fits, and the panel says in its own words that opening that link shares the summary with GitHub and that the issue will be public. Orbit never opens or submits it. Fourteen checks across `tests/preview.test.ts`, `tests/browser-scroll.test.ts`, `tests/theme.test.ts`, `tests/viewer-layout.test.ts` and `tests/diagnostics-viewer.test.ts` pass, the last two rendering the viewer inside an Orbit session of their own rather than on anybody's screen. Not measured: what the new layout costs per frame against the one it replaces, which is the figure the participant gate still wants. [viewer design](docs/viewer-design.md), [diagnostics](docs/diagnostics.md).
- `0.1.0-alpha.3` is on the npm registry, the first version published anywhere, and it was installed back from the registry into a temporary Bun home before this line was written: 95 packages resolved, and `--help`, `preflight` and `install --dry-run --json` ran from `global/node_modules/sbar-orbit` with the dry run reporting `installed: true`. The registry refused the first attempt for lack of two-factor authentication, which is a registry rule and now a documented one.
- A person can now tell an assistant to stop using Orbit, and the assistant has somewhere to put that. `orbit_usage` and `sbar-orbit usage` read and write one switch per conversation: `off` refuses every later Orbit call in that scope, `on` is only ever set at the person's explicit request, and `status` reads without changing anything. It is an adapter preference and not an authorization boundary, which the class says in its own first line, because the same user's programs can always reach the same sockets. Without `ORBIT_CONVERSATION_ID` the switch lives in the MCP connection and resets when the host reconnects; with it, the CLI and MCP share one file named by the hash of the ID, written to a temporary name and renamed into place so a half written state is never read back. An unreadable state file is a refusal that says how to repair it rather than a silent default to on, and off does not close sessions or cancel work already accepted.
- Observation stopped being one shape. `orbit_observe` takes `mode`: `image`, which now returns the metadata beside the picture rather than a bare image block, so a model that can see the frame also gets the title, tabs, pointer and dimensions in text and in `structuredContent`; and `metadata`, which answers from `session.presence` and captures nothing at all, for the tab and window checks that were paying for a screenshot to read a title. The CLI has the same two, `session observe ID --metadata`, plus `--output PATH`, which writes the decoded bytes to a new file and prints the metadata with the path, so a terminal session keeps base64 out of its context. The output path is opened `wx` at `0o600`, so it never overwrites an existing artifact and never follows a symlink into one. The MCP instructions were rewritten around all of this, and every tool result that is an object now carries `structuredContent` as well as its text. Six checks across `tests/agent-interface.test.ts` and `tests/mcp.test.ts` pass. Not measured: what the metadata mode saves in practice against an image call, on a real host with a real model reading it.
- A session can say which conversation and which project it belongs to. `conversationName` and `projectName` are optional on create, both capped at 80 characters like the names beside them, and the MCP schema tells an agent not to invent a host title it does not have. The CLI reads them from `ORBIT_CONVERSATION_NAME` and `ORBIT_PROJECT_NAME`. They exist because a person watching several agents was being asked to tell sessions apart by an agent name they all share, and they are what the viewer's conversation strip is built from. A CLI that has no `ORBIT_SOCKET` now falls back to the managed service socket instead of refusing, which is what every other entry point already did. The [portable orbit-usage skill](skills/orbit-usage/SKILL.md) carries the short version of the switch and the observation modes for hosts that select skills, and [the agent interface](docs/agent-interface.md) is the reference for the whole surface, with its own limits written down.
- A failed tool call now carries a correlation ID, and everything behind that ID stays on the machine. Every dispatched session operation records a start and an outcome into a private JSONL journal: method, action type, backend, elapsed milliseconds, hashed session and request identifiers, and a generated trace ID returned to the caller as `diagnosticId`. Nothing else crosses that boundary, because a raw exception can carry a page's own text, and the broker no longer prints unexpected errors to its stderr either, so the ID is the whole thread between a failure a person saw and the record of it. The store is treated as hostile on both sides: the directory and its files are `0o700`, opened `O_NOFOLLOW` and refused when they are not a plain single link file, rotated at one megabyte into one previous file, and rebuilt from an allowlist on read rather than parsed and trusted. A write that fails does not break the tool it was recording; it increments a counter the report carries and keeps up to 1,000 events in memory, which are lost on restart and say so. An unexpected backend exit is recorded as its own event. Five checks in `tests/diagnostics.test.ts` pass. Not measured: what the journal costs across a long autonomous run, and whether the retained history is enough to attribute a failure nobody was watching.
- One workspace that will not go no longer ends the sweep. Measured 13 September 2026: a single directory under a path this process could not write to threw out of the loop, so a run with 214 directories and 7.4 GB to reclaim removed none of them and reported only `Command failed`. Each refusal is now carried in its own `refused` list with the reason it gave, and the rest of the sweep continues. The test was run against the unfixed loop first, where it failed with the `EACCES` the fix now records.

## 0.1.0-alpha.3 - 13 September 2026

- The fresh-machine container now builds the native runtime, and found the reason it would not have run anywhere but here. In a clean Fedora 44 image with the build tools present, the bootstrap downloaded, verified and compiled, and the sway it unpacked could not load `libevdev.so.2`: it unpacks three packages rather than installing them, so everything they link against had silently been the workstation's to have. The bootstrap now ends with `ldd` and prints every missing soname with the `dnf` line for the 26 runtime packages resolved from the pinned RPMs' requirements; `preflight` asks the same question of a built runtime and reports it as a native prerequisite with that remedy, tested with a fake loader; and the container's `deps` image carries the packages. Measured 13 September 2026 on the rerun: in the `deps` image the bootstrap exits 0, the compositor it built reports `sway version 1.11`, and the helper is present; in the `minimal` image the bootstrap refuses at the compiler, as it should. What that does not show is a native session on that image, which has no display to open one on.
- `./install.sh --native` builds the private display runtime, so a Fedora machine gets native sessions from tracked source through the same command as everything else. The step is opt-in because it downloads three pinned Fedora packages and compiles the pointer helper, and browser sessions do not need it; it is skipped when the runtime is already there, refuses with the `dnf` line for the C toolchain and the Wayland and xkbcommon development files when those are missing, and reports the bootstrap's own last words when it fails. Measured 13 September 2026 on this Fedora 44 host: the bootstrap, pointed at a scratch directory so the live runtime was untouched, downloaded, unpacked, verified both protocol digests, compiled and reported sway 1.11 in under a minute, 3.3 MB on disk. The step's decisions are unit tested with an injected bootstrap; the `prerequisites` remedy for a missing runtime now names `./install.sh --native` and no longer claims to need elevation, since nothing in the bootstrap does.
- Shaped the package for `bun add -g sbar-orbit`: a `bin` entry, a `files` list that ships the runtime and the Markdown docs and nothing else, Linux and Bun 1.3 declared, `private` dropped. Measured from a `bun pm pack` tarball into a temporary consumer project and a temporary global Bun home: `--help`, `preflight`, `doctor --report` and `install --dry-run --json` all ran from `node_modules/sbar-orbit` and planned the same steps as a checkout. Nothing has been published, so the registry path is tier `Limited` and [packaging](docs/packaging.md) says exactly what was and was not shown. The fresh-machine container run was repeated against the new budget code and kept its documented shape: extract, dependency install and `doctor` pass, and both install paths refuse a host with no systemd user session by their intended messages.
- Removed every non-null assertion from the source, the way the conventions ask: a destructured first element with its own refusal in place of `argv[0]!`, typed fields for the compositor's socket and display in place of reading them back out of the environment, an `input()` accessor that names a missing pointer helper in place of `this.device!`, and `charAt`, `??` and a typed lookup table for the rest. 39 tests across the touched files pass.
- Sized the shared budget to the machine, and named the three walls it was hitting. Measured 13 September 2026 with three browser sessions open for another agent on a 24 thread, 31 GiB host: the slice stood at 453 of its 512 tasks, about 150 per settled session, and a fourth session failed inside 407 ms with a refused fork that surfaced as a browser that never published its endpoint, `pids.events max` rising by ten across one test run; with the task cap out of the way the fixed one core quota throttled the slice in 18,252 of 49,195 scheduling periods, 37%, and every further Chrome start timed out at its 20 second handshake; and with that out of the way the fixed 2 GiB sat pinned at its 1792 MiB pressure threshold with 1,569,927 `memory.high` reclaim events, inside which a browser asked for a new page hung or lost its renderer. The budget is now a quarter of the machine on each axis, floored at one core and 2 GiB and capped at four cores and 8 GiB, so a four core laptop keeps exactly the limits it had; tasks are 1536, which protects the desktop from nothing the other two do not. Weight and niceness, which are what keep the desktop responsive, are unchanged. The full suite then ran in 54 seconds against 88 to 104 before, 196 passing, with zero memory events, zero refused forks and 43 of 544 periods throttled during the run, while the other agent's sessions stayed open throughout.
- A browser session now refuses before its fork rather than after. `launchChrome` reads the slice's live counters and raises `RESOURCE_EXHAUSTED` naming the free tasks and megabytes when there is less room than a launch needs, which was measured by sampling `pids.current` every 10 ms through a start: 132 tasks at the peak of the fork burst, 139 when the endpoint is published, 150 settled. The failure message also carries Chrome's own last words now: its stderr was discarded, which is how a refused fork spent a day reported as a browser that did not publish its endpoint.
- The managed broker sweeps abandoned workspaces when it starts. `~/.cache/sbar-orbit/workspaces` held 417 directories and 7.2 GB from brokers that had been stopped or killed, because the only thing that reclaimed them was `sbar-orbit clean`, which nobody ran. A directory whose recorded owner is the fixed managed socket but another pid was written by a broker that is gone, and goes; a private broker started by a test keeps its own.
- The viewer decodes each frame with the engine's base64 decoder where it exists, `Uint8Array.fromBase64`, rather than a JavaScript callback per byte. Measured in the owned Chrome on a 67 KB frame over 60 decodes: median 6.2 ms to 3.8 ms, p90 8.3 ms to 4.3 ms. A `data:` fetch would have done the same and the page's `connect-src` forbids it, which the preview test found. The freshness readout also writes a node only when its text changed, and `status --watch` polls at the panel's cadence, one second while an agent acts and up to five when nothing answers, instead of a fixed second.
- The MCP server reads its version from `package.json` instead of carrying a copy that a release would have to remember. The launcher's help now lists every verb the CLI accepts; `preview open`, `preview browsers`, `session observe`, `pause`, `resume`, `journal`, `restore` and `account save` all worked and none was written down. A GitHub workflow runs the typecheck, the public audit and the long dash rule on every push, which is what a hosted runner can check; the suite itself needs a delegated cgroup and stays local.
- Removed the website's deployment workflow, and with it the reason to keep a Cloudflare API token in the repository's secrets. It had never deployed anything: both of its runs failed on the missing secret, while the site that is live was put there by a person running `wrangler deploy` from a machine that is already logged in. Deployment is now that command and nothing else, so a push to `main` deploys nothing and no credential lives in the repository. The site stays where it is, on Workers with the custom domain declared in `website/wrangler.jsonc`.

## 0.1.0-alpha.2 - 13 September 2026

- Fixed the release smoke test asking the packaged browser for a format it stopped producing. Frames became JPEG on both backends, and this check still read the bytes for a PNG signature, so the first packaging run of this release failed on a capture that had worked. It now reads the format the frame declares and checks that frame's own magic bytes, which is the rule `tests/frame-format.ts` already holds the suite to. Caught by running the documented release commands rather than by reading them.

- Took the lines and the colours out of the viewer, and the project's vocabulary with them. Nothing draws a border any more, including the hairline rings that were borders wearing a shadow's name, so separation is carried by the surface a thing sits on and the shadow it casts; the surfaces had to move about eight per cent apart to do alone what a line was helping with. The palette is white, black and the greys between, which means state can no longer be a green light and an amber one. It is brightness, motion and words instead: bright and moving is working, bright and still needs you, dim is open, dimmest is done. That also survives being read by somebody who cannot separate red from green, which the light it replaces did not. `prefers-reduced-motion` removes every animation, so the halo that separates working from paused is a shadow rather than a keyframe; the four states were rendered with motion switched off to check they stay apart rather than assumed to.

- Gave the picture a way to be bigger, and said why the other one is greyed out. **Make it bigger** hides the rail, the panels and the heading and lets the picture use the height of the window as well as its width, computed from the window height and the picture's shape so the canvas and the box the pointer is placed in stay the same rectangle; the pointer lands on its coordinate in both views and both are asserted. It changes nothing about the session, so unlike **Screen size** it needs no pause, which is the answer to "let me see it properly" that does not move a coordinate out from under the assistant. **Screen size** still waits for a takeover, and now says so beside itself rather than being greyed out in silence.

- Rewrote the viewer for somebody who has never read this repository. Pause, resume and stop are Take over, Hand back and End session; running, paused and closed are Open, You are in control and Finished; "SbarOrbit: Fill field · working · Step 12" is "SbarOrbit is filling in a box right now · step 12"; a frame age in seconds is how old the picture is. A session that is running with nothing in flight now says Open rather than Working, because saying otherwise is the kind of small lie that teaches a person to stop believing the screen. The state itself moved to `data-state`, which is what a test should read, and the two browser tests now read it instead of the words. The short session identifier appears only when two cards would otherwise be identical, which is what it was for. The cost readout is kept and moved into a Technical details disclosure: it is the only instrument for what the viewer costs and it is not a sentence anybody needs first. The selects lost the platform's arrow and casing; the list one opens is still the browser's and cannot be styled, and a hand built listbox would have bought that one popup with a new keyboard model and a new accessibility tree.

- Wrote down what is wrong with the desktop panel's settings before changing any of it. Eighteen rows in seven groups answer seven questions: the glow is three settings, the notifications are two, and where the dot sits is four, one of which is already done by dragging the mark. The words are the project's rather than the reader's, the four state colours ask the reader to know Orbit has four states, nothing is ranked so a login switch reads like a transparency slider, and the window opens on a right click on a dot that is designed not to be noticed. The proposal is five decisions on one screen with the rest behind a disclosure, and it names the two parts that are not cheap: an eight place picker is a new widget that has to be operable from a keyboard, and collapsing two pairs of switches has to keep reading and writing both keys or an existing settings file loses a combination it holds. Nothing is built. [The study](docs/panel-redesign.md).

- The viewer opens as a window rather than a tab, and it is somewhere a person can stand. `preview open` and the desktop mark hand the link to a browser instead of printing it, in a window with no tab strip and no address bar, which is Chromium's `--app=` and nothing more: no manifest, no installation and no fixed port, because the link's port is allocated per broker and its access token lives in the fragment. An installed progressive web app is scoped to an origin, port included, and would be launched at `/` carrying no token, so it is a different change rather than a tidier version of this one. Browsers are found the way the desktop finds them, by the http scheme handler in a desktop entry, with the `WebBrowser` category required as well so an application that registers the scheme to catch its own sign-in links is not offered as somewhere to read the viewer. Flatpaks come out of the same scan, which matters on a desktop whose default browser is one. The Firefox family has no app window: site specific browsers were removed in Firefox 86 and no release build carries a replacement, so nothing is invented for them and they open a tab, which is why an unset choice passes over a default browser that cannot open a window and takes the first installed one that can. The family is read from the executable's name, and where that says nothing, from the private window action every browser ships and the two families spell differently, which is what identifies a Chromium build named Helium. Both choices are settings, `viewerBrowser` and `viewerAppWindow`, under **The viewer**. Spawning is not opening, so a browser that starts and rejects its arguments is given a moment for its exit code to arrive rather than being reported as a window that appeared; an immediate success is the forwarded second invocation and is treated as one. Tested against desktop entries written to a temporary tree, in the shapes this machine carries: a flatpak with file forwarding, a system Chromium, an Edge progressive web app, an unrelated launcher that handles http, and a browser the desktop hides. Then run for real, inside a private display rather than on the person's screen: `--app=` against a cold browser produced a window with no tab strip and no address bar, carrying the token fragment and connected; the same command against that running browser exited at once and a second chromeless window appeared beside the first. Desktop entries are Linux, so macOS and Windows still get a tab, and that is now written down rather than left implied.

- Rebuilt the viewer on a design system of its own, and made following the desktop a switch rather than the default. Every colour is a token declared once, elevation is five surfaces rather than five shadows because a shadow on a dark ground is nearly invisible, and the stage inverts the scale: it sits in a well below the page, inside a strong border and the deepest shadow, so the one thing that matters is cut into the ground and everything else is a step up from it. Sessions moved from a drop-down to a rail of cards, which is the whole of navigation: the drop-down showed one session at a time and said nothing about the rest, so a person running several agents could not see which one had stopped without opening it. The rail is built from `session.list` alone and holds no second live image, because every live image is a capture, an encode and a decode on each poll, and that cost is what the participant reported. Where the model is working now has three signals reading from one fact, an action in flight: the card's light breathes, the stage glows, and the activity line names actor, action, state and step; a running session with nothing in flight is open, not working, and none of them fires. `prefers-reduced-motion` removes all of it and each signal still reads as a colour. The agent's pointer dims over a stale frame instead of disappearing, because at the default one frame a second it had been invisible most of its life. The desktop's generated palette is now emitted under `:root[data-palette="desktop"]`, the attribute the switch writes, so Orbit's own palette is what every machine shows until somebody asks otherwise; an unscoped rule applied the desktop's colours to anyone who happened to have matugen configured. ## 0.1.0-alpha.1 - 2026-09-10

Initial public alpha, following private local prototypes.

### Added

- Local broker, CLI and MCP adapter for tool-capable agent hosts.
- Owned headless browser sessions with separate profiles and ordered actions.
- Optional Canvas viewer with pause, scoped manual input, resume and stop.
- Fedora private Wayland/Xwayland display backend and Unicode paste.
- Named account snapshots and cooperative selected-file reservations.
- Shared Linux CPU, memory, swap and task limits; process-tree cleanup.
- Source packaging, privacy checks, test fixtures and concise architecture documentation.
- Experimental read-only Hyprland focus telemetry and human takeover trial.

### Validated

- Scripted 10-minute browser/viewer run at approximately 5 FPS.
- Browser and native lifecycle, clipboard and file-reservation tests.
- Claude Code and Codex model-host browser/native examples in local trials.

### Limitations

- Fedora/Linux alpha; macOS and Windows adapters remain unverified.
- Display separation is not a security sandbox.
- Human trial confirmation, broad account compatibility and clean-machine installation remain open.
