# Current completion status

Updated 6 November 2026.

Original registered Linux applications, including browsers and terminals, use
normal owner state on numbered workspaces. Hidden substitute desktops, copied
profiles and the browser viewer are absent. Native input and capture use actual
loaded-source and compositor-ABI verification, not a historical static hold.

[The 22 October report](native-acceptance-0.3.0.md) separates a 22-application
opening/capture/closure matrix from real editing, clipboard, Arabic, Save and
Chrome account UI tasks. Maps completed later activation-token checks; its earlier
failed opening stays in the [historical report](native-opening.md).

The [current acceptance index](acceptance.md) also includes 26 October original
application selection and rejected-input recovery checks, Calculator input and
normal closure, and the controlled transport latency measurement. The historical
selection-collapse cause is still unestablished. These results do not establish
universal application, account or concurrent-owner compatibility.

The November source now provides bounded public snapshot refs, typed stale
refusals and skeleton/root traversal. GTK 4.22.5 realization UUIDs and the
explicit Qt 6.11.2 Widgets helper qualify supported mutation targets. Original
GTK Calculator and Qt Designer stale refusals were measured; original Thunderbird
skeleton/root traversal reached one message row without the cap. See
[snapshot refs](snapshot-refs.md) and
[Qt acceptance](native-input-reliability.md#scoped-refs-and-explicit-qt-widgets-qualification-6-november-2026).

Residual named GTK geometry has a bounded pixel-backed correction, Electron
renderer accessibility has an explicit registration decision and measured
original VS Code tree, and registered opening reports proven forwarding and
same-sample native minimum constraints. These have operation records in the
[acceptance index](acceptance.md); unknown evidence stays unknown.

Semantic Action/EditableText/Value dispatch uses read-only preparation, final
current authority and guarded single SEND. Original GTK button/text effects and
Qt button/checkbox/text effects were measured. A Nautilus grid cell's only
exported action was `listitem.scroll-to`; its accepted response did not open the
folder. No semantic activation or automatic replay is inferred from that reply.
GTK checkbox and final Nautilus ref-click acceptance remain unmeasured. This
campaign is closed by owner scope decision, with those gaps preserved here.

Windows/macOS source prototypes expose status and window metadata. Production
handoff, capture, registered opening and writes remain unavailable because
initial native window lifetime and real-machine acceptance are unqualified.
One existing Win11 VM boot was stopped by graceful ACPI shutdown after severe
host memory pressure, with no guest action acceptance. No macOS guest or
registered GNOME/KDE desktop was found in the bounded local inventory. Other
Linux compositor adapters and XWayland control remain unimplemented.

The comparative efficiency program is deferred: no compatible real baseline
and candidate throughput result or 1.8x gain is established. Universal
application/account and concurrent-owner compatibility remain unproven. See
[support tiers](support-tiers.md) and [remaining work](roadmap.md).
