# Current completion status

Updated 27 October 2026.

Original registered Linux applications, including browsers and terminals, use
normal owner state on numbered workspaces. Hidden substitute desktops, copied
profiles and the browser viewer are absent. Native input and capture use actual
loaded-source and compositor-ABI verification, not a historical static hold.

[The 22 October report](native-acceptance-0.3.0.md) separates a 22-application
opening/capture/closure matrix from real editing, clipboard, Arabic, Save and
Chrome account UI tasks. Maps completed later activation-token checks; its earlier
failed opening stays in the [historical report](native-opening.md).

The [current acceptance index](acceptance.md) also includes 26 October original
application selection and rejected-input recovery checks, Calculator input and
normal closure, and the controlled transport latency measurement. The historical
selection-collapse cause is still unestablished. These results do not establish
universal application, account or concurrent-owner compatibility.

Other Linux compositor adapters, XWayland control and native Windows/macOS
opening and control are not implemented. Universal application and account
compatibility remain unproven. See [support tiers](support-tiers.md) and
[remaining work](roadmap.md).
