## 3. P1 blocker: image observation is not proven input-pure

**S:** [image capture begin:439-452](<../../src/native/session.py#L439-L452>) calls [ensure_pointer:360-369](<../../src/native/session.py#L360-L369>) -> ghost-cursor -> pointerCmd(kind=3). In [pointerCmd:2318-2364](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L2318-L2364>), flushPump(address) at 2329 occurs before the cursor-only return at 2363. [flushPump:2206-2215](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L2206-L2215>) can run a pending click press/release callback synchronously or finish drag motion/release. This transitive input-effect reachability contradicts treating every cursor refresh as strictly render-only, even though the Python helper's intent/docstring is render-only. It is not a measured incident.

Image observe, text fallback-to-image, both and pixel-digest baseline share that path. Successful text-only observation returns before begin at [426-434](<../../src/native/session.py#L426-L434>); cached presence does not invoke it. Cursor refresh also calls resolve(wake=true), which can install shared-selection handling and unsuspend the target at [1738-1751](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L1738-L1751>), updates cursor motion and damages the monitor. Pure pixel capture and UI-presence effects therefore require separate capability classification.

**Decision, not implementation:** investigate an observation route that does not refresh pointer/cursor or flush pumps. Qualify its capture completeness, owner preservation and rendering behavior before P1 read concurrency. Alternatively classify refresh as coordinated effectful work and keep it outside pure-read grants. No plugin patch/reload is authorized by this inventory. P1 input-pure observation remains blocked until that choice is implemented and independently tested.

### Subsequent implementation update

The internal `passive-v1` worker/backend seam now omits cursor refresh across
image, text, both, baseline and settled/resampled captures. It uses detached
worker metadata without sibling enrollment or writer pointer clearing; the
backend requires an exact omission acknowledgement and does not update writer
selection/scale state or fall back to a legacy read. Passive text never widens
to pixels when accessibility is unavailable. Legacy observation is unchanged.
See the [implementation ledger](multi-view-implementation.md#5-internal-passive-observation-seam)
for test evidence and limits. This narrows the original source-reachability
blocker, but does not establish global input quiescence or P1 native acceptance.
No compositor plugin source, loaded instance or broker was changed/restarted.

## 4. Cancellation and drain: known boundaries, not receipts

- **S:** [client abort:84-118](<../../src/ipc.ts#L84-L118>) destroys the HTTP request locally; broker dispatch does not pass request.signal to session work. [MCP off:73-83](<../../src/mcp.ts#L73-L83>) explicitly does not cancel accepted work. Neither proves endpoint quiescence.
- **S:** [pause:617-628](<../../src/session.ts#L617-L628>) waits session.tail then native pause. Observe has a different admission path. [native pause:287-317](<../../src/native/existing.py#L287-L317>) serializes on the Python session lock and sends application-control pause; the plugin pause branch cancels keyboard preparation and sets paused. It is not a proof that all already accepted pointer callbacks have drained.
- **S:** [pointer wait:385-393](<../../src/native/session.py#L385-L393>) polls ghost-state motion_active for up to 8 seconds. [ghost-state:2779-2799](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L2779-L2799>) reports pumps.contains(address), not consumed application events, all held state or an accepted/settled sequence. An empty map or expired TTL is not a quiescence receipt.
- **S:** [worker close:241-272](<../../src/native-worker.ts#L241-L272>) reaps its owned worker after bounded waits; [forced session close:583-615](<../../src/session.ts#L583-L615>) can mark broker state closed while recording plugin-release failure. Original application event processing is not rolled back by worker death.
- **S:** [handback:930-987](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L930-L987>) removes cursor entries and tracked client state; pumpTick later erases pumps lacking a cursor. ghost-release restores held pointers/keyboards but does not supply a transaction-specific cancel/drain receipt. Do not infer equivalent cancellation from these different mechanisms.
- **U, blocking:** exact accepted/settled sequence accounting, revocation during silent click delay, flush-versus-cancel semantics, callbacks racing handback/resume, pressed-state ownership across fence changes, drain after transport loss/compositor restart and application async effects. The safety specification requires quarantine until qualified owned drain, not reassignment on timeout.

## 5. Frozen initial decisions, not current wire/API implementation

1. **Cohort:** one explicitly qualified Linux Hyprland Wayland adapter/build/application combination only. Broker, TS worker framing, Python worker/keyboard/transport, plugin immediate handlers, deferred pumps, cleanup and opening/presentation endpoints must negotiate a compatible protocol before writer opt-in. A source hash/ABI match alone is not proof of the new coordination protocol. No new schema/version number or capability is claimed here.
2. **Fence closure:** immutable caller/grant/consent, broker/adapter/binding/topology generations, resource fences and dispatch identity must reach the actual effects listed above. Include preparation protocol effects, every delayed press/motion/release and forced flush, not just broker admission or pointerCmd/cmdKey entry. Cleanup uses a distinct owned, fenced reconciliation policy so revocation cannot authorize new presses or release human-owned state.
3. **Compatibility:** device-resource-wide writer coordination includes old single actions, batches, manual control, lifecycle, opening/presentation and relevant maintenance/direct routes. Unknown/incompatible active writers block opt-in. Do not restart/stop other tasks. Same-user arbitrary direct IPC is outside a hostile-process security guarantee; supported direct Orbit writers still need cohort enforcement or explicit refusal. Feature disable retains unresolved fences/quarantine until drain.
4. **Initial conservative bounds:** [plan limits:177-197](<multi-view-plan.md#L177-L197>) are frozen as proposed upper bounds: off by default; 2 views/conversation, 8/device; 4 conversations/device; 0 extra models; 1 writer/shared input resource; 1 capture/device; action descriptors 8/conversation and 32/device with finite deadlines; 1024 recovery entries and 1 MiB/device; 1 latest unconsumed observation/view; observation memory 16 MiB/view and 32 MiB/device; 0 automatic retries of possibly delivered effects; no extra seats/cross-device execution; no raw capture/text/clipboard telemetry retention by default. These limits are not implemented capacity measurements.
5. **Use stricter existing bounds:** [worker:220-235](<../../src/native-worker.ts#L220-L235>) caps 128 queued requests and 65536-byte frames; [worker cache:130-135](<../../src/native/session_worker.py#L130-L135>) has request/metadata bounds; [session:353-354](<../../src/session.ts#L353-L354>) caps action IDs at 10000; [claim:1087-1110](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L1087-L1110>) caps 16 client leases and 64 retained windows/client; [keyboard preparation:1884-1896](<../../experiments/ghost-cursor/plugin/ghostinput.cpp#L1884-L1896>) caps producers/pending operations and uses 3-second expiry. These are different resource domains, not interchangeable multi-view slots. Account encoded/decoded images, trees, helpers and queues, not frame count alone.
