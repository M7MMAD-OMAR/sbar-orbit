# Owned reader drain and memory proof audit

Status: **source audit and integration proposal only**, 4 November 2026. No native desktop operation, test, build, graph refresh, process signal, resource probe or commit was performed for this audit. Shared activity and original applications were not touched. No phase gate passes. The proposed read accounting ledger is not a process supervisor, memory allocator, authority grant or OS quiescence proof.

Scope: current pixel helper, cold/warm accessibility helpers, framed native worker and their retained buffers. [Cohort limits](<multi-view-cohort.md#L52-L84>) and the [ingress inventory](<multi-view-ingress.md>) remain design context. Facts below describe inspected source, not a live process census or RSS measurement.

## 1. Proof vocabulary

| Observation | What it establishes | What it does not establish |
| --- | --- | --- |
| Root wait/poll reports exit | That particular retained child ended/reaped under its process handle | Descendants ended, process group empty, inherited FDs all gone, foreign provider work stopped or buffers released |
| A pipe/socket is closed or EOF arrives | This communication path is no longer usable/has no writers retaining that particular endpoint | Every descendant died; another process may close its inherited pipe and continue |
| Signal was sent to PID/group | A signal attempt targeted the identified process/group at that moment | All targets received it, exited, were reaped or could not escape into another session/group |
| Parent-death signal configured | The configured helper root has a parent-lifetime defense, with the checked startup race | Every future descendant shares the same defense or is accounted for after root death |
| Same cgroup/budget observed | A sampled process is under the inspected resource ceiling | Exclusive ownership of the shared cgroup, per-operation credit, zero members after cancellation or isolation from unrelated tasks |
| Generation-bound owned leaf is verified empty | Only with stable scope identity, no new admission and accounted membership, evidence that this owned scope has no live tasks | Original app/provider work outside the scope stopped, application effects rolled back or allocator pages immediately returned |
| Valid reply/promise settlement | Protocol operation returned or caller stopped waiting | OS/helper quiescence, cancellation propagation, descendant death or release of external references |

The required future receipt must name its narrow domain: **owned reader work**, not all device input or original application state. Root reaping, channel closure, helper generation retirement, descendant termination and retained-data release are separate facts.

## 2. Exact lifecycle map

### Pixel capture

[bounded_capture:135-208](<../../src/native/session.py#L135-L208>) checks an absolute cooperative deadline, then starts one subprocess with stdout/stderr pipes at 147-148. It does not request a new session/process group or create a dedicated per-read cgroup. It drains those pipes through selectors, waits for the child under remaining work budget at 166, and in finally kills the **child PID** if still alive, waits up to the 3-second cleanup reserve, closes its streams and writes private diagnostics at 186-203. Cleanup errors remain errors or an exception group, not successful capture.

**Known:** successful return includes root completion and attempted stream cleanup. **Not proven:** descendants are absent, a timed-out root's descendants died, escaped descendants cannot hold independent resources, or a failed cleanup releases operation credit. The selector can time out while a descendant retains a pipe. Conversely pipe EOF plus root exit can coexist with a descendant that closed its pipe. No descendant receipt is produced.

The reader must reserve before [begin/capture:455-508](<../../src/native/session.py#L455-L508>), not after pixels arrive. Geometry retries share the operation deadline; they may replace detached geometry but are not separate free operations. [Capture cleanup:186-207](<../../src/native/session.py#L186-L207>) occurs outside the work deadline and can fail. A caller's elapsed timeout is not safe slot reuse.

### Cold accessibility

[read_tree:39-76](<../../src/native/a11y.py#L39-L76>) uses subprocess.run with capture_output and a timeout, default at most 5 seconds or remaining observation time. The query's nominal provider budget is at most 1500 ms. There is no repository-owned per-query process/session scope or retained child handle around this call. The repository delegates subprocess timeout/root cleanup to the Python library, without adding descendant proof. Exceptions are translated to unavailable.

[Cold dump initialization:294-337](<../../src/native/a11y_dump.py#L294-L337>) imports GI, initializes AT-SPI, locates an external application's accessible tree and serializes the result. Cooperative traversal deadlines do not forcibly preempt arbitrary provider/library calls. The parent slices stdout to 2000000 bytes **after subprocess.run has captured it**, so that slice is not a streaming pipe or peak-memory bound. Final [300-node/16000-byte trim:9-36](<../../src/native/a11y.py#L9-L36>) is also after the raw reply has been received and parsed.

**Unknown:** descendants created by runtime/libraries, buffering before return, root/descendant outcome on a timeout and foreign D-Bus service activation/lifetime. Do not claim an unavailable tree is a drain receipt. Original app and shared accessibility bus services are not owned cleanup targets.

### Warm accessibility: stronger ownership, incomplete descendant drain

[Existing session creation:48-57](<../../src/native/existing.py#L48-L57>) creates a warm host only when explicitly opted in. [A11yHost._start:124-154](<../../src/native/a11y_host.py#L124-L154>) starts the helper with start_new_session=True, private inherited socketpair, a generation and expected parent; stdout/stderr go to DEVNULL. [Helper startup:30-48](<../../src/native/a11y_host_worker.py#L30-L48>) checks parent identity around configuring a SIGKILL parent-death defense, disables core dumps, and clamps helper virtual address space to at most 512 MiB and file descriptors to at most 64, respecting stricter inherited limits. These are not measured RSS or device-total bounds.

[observe:188-240](<../../src/native/a11y_host.py#L188-L240>) serializes helper access, includes lock/startup/query in a monotonic deadline, checks generation/request identity and does not retry. On admitted failure it calls _destroy; a failed destroy is suppressed into the fixed transport error while the retained process reference can remain for later cleanup. Preflight/queued callers that did not acquire the operation lock do not own that helper and must not kill it.

[_destroy:68-104](<../../src/native/a11y_host.py#L68-L104>) invalidates generation and closes the socket first. If root.poll is still None, it attempts killpg(root.pid, SIGTERM), waits 0.1 seconds for the root and, **only if that root wait times out**, attempts group SIGKILL and waits another 0.3 seconds. If the root is already exited, it only waits for that root. It clears _process after root wait succeeds. If root cleanup fails it retains _process and refuses restart, a useful quarantine of the known root handle.

**Specific proof gap:** a root may exit on TERM while a descendant ignores TERM. Root wait then succeeds, SIGKILL is not attempted, no group-empty check occurs, and _process is cleared. Likewise, a root already exited can leave descendants without any group signal in this branch. This is a source-level possibility, not a measured survivor incident. start_new_session plus killpg is stronger than root-only kill, but root.wait does not establish the whole group died. Numeric PGID reuse/escape and membership stability also need an owned-generation contract before a later cleanup attempt.

[Warm serve:161-185](<../../src/native/a11y_host_worker.py#L161-L185>) sends a reply then runs gc.collect and keeps provider state alive. Its 60-second idle socket timeout is a lifetime fallback, not an immediate cancellation receipt. [Provider:109-158](<../../src/native/a11y_host_worker.py#L109-L158>) retains GI/AT-SPI context/listeners, pumps at most 16 pending events per call, performs provider reads and refreshes caches. A serialized reply means that request's handler returned, not that persistent provider memory, all event callbacks, external application RPC activity or descendants are gone.

[Pause/close:281-360](<../../src/native/existing.py#L281-L360>) retires the warm host; failed host.close keeps the host reference and propagates cleanup failure. This preserves ownership better than forgetting an unreaped root, but its scope guarantee is still limited by _destroy above. No global/provider kill is a permitted repair.

### Framed native worker and inherited resource scope

[NativeWorker.create:95-123](<../../src/native-worker.ts#L95-L123>) spawns the existing worker under the current inherited budget with piped stdin/stdout and a private log FD. It does not allocate a dedicated worker process group, session or reader cgroup. [Request:220-239](<../../src/native-worker.ts#L220-L239>) queues per worker, begins a 20-second timer after reaching the queue head (75 seconds for opening), and rejects on timeout. [abort:137-146](<../../src/native-worker.ts#L137-L146>) rejects the pending promise, ends stdin and starts asynchronous close, recording recoveryFailure if cleanup fails. Promise rejection therefore precedes any proven reader drain.

[close:241-272](<../../src/native-worker.ts#L241-L272>) waits up to 15 seconds, then sends SIGCONT/SIGTERM to the worker **PID**, waits 3 seconds, then SIGKILL to that PID and waits another 3 seconds. [Constructor close listener:73-93](<../../src/native-worker.ts#L73-L93>) uses the child close event and log release. This can establish root/stream lifecycle, not all descendant termination. A descendant can close inherited stdio and continue, while a retained pipe can instead delay close. NativeWorker's root-close signal is not a per-operation descendant receipt.

[Python worker finally:89-163](<../../src/native/session_worker.py#L89-L163>) normally closes its session after stdin EOF, but EOF does not interrupt a currently blocked synchronous native/provider call, and forced root termination can skip Python finally. [Backend close:292-323](<../../src/hyprland.ts#L292-L323>) closes that worker, attempts lease reaping and diagnostic retention, then removes its private directory on success. Lease handback and workspace-file cleanup do not prove helper descendants died or provider work stopped.

[require_budget:4-15](<../../src/native/budget.py#L4-L15>) checks the shared sbarorbit.slice has finite limits no larger than 4 CPU cores, 8 GiB memory and 1536 tasks, with zero swap. It is inherited aggregate containment, not an exclusive per-reader scope. **Never kill the shared slice, broker process group or original app to obtain a read receipt.** [auditProcessScope:7-32](<../../src/process-scope.ts#L7-L32>) samples thread child lists/cgroups; indexed callers are tests, and sampling is not an atomic supervisor or kill/drain protocol. [NativeLease:149-218](<../../src/native/lease.py#L149-L218>) binds invocation/cgroup identity and samples membership; its indexed constructors are experiments/tests, not NativeWorker production supervision. Neither helper should be advertised as an already wired descendant receipt.

## 3. Memory ownership by representation

| Domain / exact seam | Existing bound or allocation | Reservation proof still needed |
| --- | --- | --- |
| Capture pipe buffers, [135-179](<../../src/native/session.py#L135-L179>) | bytearray output ceiling 16 MiB PNG or 64 MiB raster, stderr 65536 bytes; checked after extending each up-to-65536-byte chunk. bytes(data) adds a full immutable copy while source storage can still exist | Reserve raw capacity, one-chunk overshoot, copy overlap, allocator slack, pipe/kernel buffers and child baseline before spawn. Output length is not root/helper RSS |
| Raster crop, [100-113](<../../src/native/session.py#L100-L113>) | Source raster plus row slices/filter bytes, joined rows, compressed output, PNG chunks and concatenations coexist. | Settling and geometry resampling, [499-519](<../../src/native/session.py#L499-L519>) | A previous frame, current capture, hashes and transient retry/crop buffers can overlap | Charge whole operation peak, not one latest image only; retain scratch reservation until each replaced representation has no owner |
| Encoding and metrics, [520-598](<../../src/native/session.py#L520-L598>) | Original image bytes, base64 byte output, decoded Python string, frame dictionaries and json.dumps tree measurement; base64 length is 4 times ceil(rawBytes/3) | Omission acknowledgement reports mode, not memory. imageBytes is reconstructed payload length, not all representations or RSS |
| Worker cache/serialization, [ReplyCache:18-48](<../../src/native/session_worker.py#L18-L48>), [framing:130-158](<../../src/native/session_worker.py#L130-L158>) | At most one retained image, request/result metadata up to a pre-admission 16 MiB threshold plus terminal allowance, json.dumps/UTF-8 copies for sizing and outbound line | One retained image is additional ownership. Bound broker serialization, socket buffers, receiver refs and cancellation separately |
| Cold accessibility, [read_tree:39-76](<../../src/native/a11y.py#L39-L76>) | capture_output stdout/stderr are collected before the 2 MB parse slice; parsed tree before trimming to 300 nodes/16000 node bytes | Streaming limits, child baseline GI/provider memory and parse/object overhead missing from current final-node metrics |
| Warm accessibility, [host:17-24](<../../src/native/a11y_host.py#L17-L24>), [_read:156-186](<../../src/native/a11y_host.py#L156-L186>), [helper send:76-80](<../../src/native/a11y_host_worker.py#L76-L80>) | 64 KiB request, 256 KiB response; helper serializes before checking response length; receiver bytearray->bytes->decoded string->parsed dict. Persistent provider baseline remains while idle | Charge host instance baseline separately from request/result bytes, plus parse/serialization temporaries and socket buffers. 512 MiB helper virtual-address cap is neither 32 MiB RSS nor a shared-device proof |

Numbers above are source limits or representation formulas, **not measured peak memory**. Runtime object layout, base64 string representation, allocator retention, compression workspace, Python/GI/GLib imports, shared library mappings, helper/provider state, kernel buffers and the original application's independent work are separate domains. Do not invent a constant overhead multiplier as a hard guarantee. Reference counts in a logical ledger can bound owned logical bytes only if every producer, retained reply, audience reference and helper reservation participates.

A warm helper needs an **instance baseline reservation** across requests, not a new free helper for every released frame. Cold helpers need per-operation baseline/scratch reservations until owned drain. Original apps and external shared accessibility services stay outside Orbit's killable scope; qualify/cap Orbit-attributable workload without claiming a read ledger controls their total RSS.

## 4. Narrow next integration seam

The next safe increment is an **internal one-operation owned reader adapter**, initially pixel-only, with no public multi-view enablement or automatic subscriptions. Do not wire a ledger release callback to existing promise.finally, child close, root.wait, passive omission acknowledgement or elapsed timeout.

1. **Before worker enqueue:** allocate a private operation identity and bounded descriptor, reserve queue credit and conservatively budget encoded/decoded/result/scratch/helper representations. Carry one monotonic end-to-end deadline including queue wait; current [observePassive:431-447](<../../src/hyprland.ts#L431-L447>) worker deadline alone excludes that wait. If allocator/scratch bound cannot be enforced, refuse before spawning rather than reserve a guessed small amount.
2. **Before helper execution:** create an exclusive owned child scope with generation-bound identity and a trusted supervisor that survives helper-root death. Enroll the helper before it can fork or issue work. A dedicated verified cgroup leaf is a candidate; mere inherited shared budget, PGID alone or a late /proc ancestry sample is insufficient. Original application and shared service processes must never enter this owned kill scope. Confirm actual available delegation/permissions instead of inventing them.
3. **Cancellation path:** bind cancellation to that operation across broker queue, TS worker frame and Python helper/supervisor. Cancel queued untouched work without spawning. For started work stop admission/delivery, ask only its owned scope to stop, and retain slot/scratch credit during termination and channel draining. No concurrent write/clipboard/setup cleanup is granted by reader cancellation.
4. **Trusted completion witness:** record exact operation and supervisor/scope generation, no-more-dispatch boundary, root outcome, outstanding channels/requests, owned descendant membership and final empty/quiescent evidence. For a persistent warm instance, separate per-request completion proof from instance lifetime/baseline cleanup. If a group member cannot be proven stopped or a scope was replaced, report unknown, quarantine its reservation and refuse conflicting reuse. Keep a retryable owned cleanup handle rather than dropping it after root.wait.
5. **Retained result transfer:** after successful read and scoped completion, move actual encoded/tree ownership into the retained-result reservation; release only scratch known no longer owned. Keep delivered references independently charged until all are released/revoked under the retention contract. Revocation suppresses future delivery but does not erase references already delivered or prove GC returned pages.
6. **Escalation/recovery:** bounded scope termination can fail; unresolved records remain bounded safety markers. Never release on TTL, recreate authority from stale client handles, terminate an unrelated task or restart shared services. Broker crash needs supervisor-backed cleanup/recovery evidence before reclaiming credit.

**Do not initially include cold/warm accessibility in a claimed descendant-drained cohort.** Add bounded cold streaming and qualified scope supervision first. For warm mode additionally prove post-request provider behavior, event handling and instance baseline accounting; closing a socket or gc.collect is not the proof. A future external-provider cancellation claim needs provider-specific evidence and cannot be obtained by killing the owner's original application.

## 5. Required owned-fixture and qualification evidence, not executed here

- Root exits promptly on TERM while a same-group child ignores TERM, closes inherited stdio and continues: reservation stays occupied until descendant proof, including root-already-exited branch.
- Descendant retains a pipe; root closes; helper sets a new session/group; parent dies before/after supervision arms; identity/PGID/cgroup generation replacement: no broad kill or false receipt.
- Queue cancellation, deadline expiry during provider/capture syscall, late valid reply after revoke, failed kill/reap, malformed/oversized framing and broker/worker restart: exactly one terminal accounting decision, unknown drain never frees credit.
- Raw PNG ceiling, raster/crop worst overlap, base64+JSON copies, cold stdout/stderr overflow, warm serialized-size overflow, persistent helper baseline and retained external references: allocation admission precedes work, not post-hoc subtraction.
- Successful image/text reply with helper still alive is classified by its exact scoped contract, not assumed root/descendant death. Owned native qualification later measures actual memory/preservation separately from synthetic tests.

**Unresolved blockers:** trusted per-operation reader supervision; descendant-empty/quiescent evidence; cold streaming bounds; persistent helper baseline/instance drain; end-to-end cancellation; every-representation memory reservations; crash recovery and safe cleanup-handle retention. The current source provides useful local timeouts, error propagation and some root quarantine, but not the complete reader drain/memory guarantee. This audit does not change runtime behavior or pass a phase gate.
