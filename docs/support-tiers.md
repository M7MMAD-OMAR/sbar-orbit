# Support tiers

What Orbit is known to do, on which host class, on what evidence, and as of when.

This file exists so that a person installing Orbit on a machine this project has never touched can
tell, before they file anything, whether they have found a bug or have simply become the first person
to run it there. Those are different reports and they go to different forms.

**Orbit is measured on exactly one host class: Fedora 44, wlroots, cgroup delegation.** Every row
below that names another platform is reasoning about vendor documentation, not a test, except: the
Linux rows marked `Limited`, which since 14 September 2026 come from containers of those families run
on the measured host; the Windows rows, which since 16 September 2026 come from a Windows 11 guest;
and the macOS rows, which since 18 September 2026 come from a GitHub `macos-26-arm64` runner that ran
Orbit's own suite, install, broker and containment experiment.

Run `sbar-orbit doctor --report` before reading further. It is local, it needs no broker, and the
`tier.assigned` it prints is the row that applies to you. It is safe to paste into a public issue, and
you should still read it first.

## The vocabulary

Five tiers, because the evidence has five states and collapsing them prints a pass over a recorded
failure. The definitions are in [porting.md section 2](porting.md) and are repeated here because this
is the file the tracker is judged against.

| Tier | Exact promise |
|---|---|
| **Measured** | A named test in [validation.md](validation.md) ran on a host of this class and passed, and the command that reproduces it is in this repository |
| **Limited** | It ran here and passed inside a stated limit: a fixture rather than the real thing, or a subset of the capability. The limit is printed beside the tier, never omitted |
| **Failed** | It ran here and did not pass. The result is preserved, not retried into silence |
| **Reasoned** | The platform documents the primitive. No host of this class is in this project's reach and no test has run on one. Installing here produces a test report, not a bug report |
| **Refused** | A primary source says it cannot work. Orbit throws `UNSUPPORTED` rather than degrading, and the tracker does not accept a bug for it |

`Measured` is never awarded by a probe. The most a capability probe can say is that your host is the
same class as the one the measurements were taken on, which is a reason to expect a test report rather
than a bug report. `bun run verify` is how a host earns anything stronger.

A `Measured` row resting on one external host prints `Measured, 1 host, issue #N` in its evidence
column. That is the evidence column doing its job, not a sixth tier.

| Shared resource budget | Limited, and **advisory**, weaker than both other platforms | A registry of process groups: membership from `proc_listpids(PROC_PGRP_ONLY)` and footprint from `proc_pid_rusage`, both kernel readings, with a utility QoS clamp as the scheduling policy the system applies. `requireResourceBudget()` returns `enforcement: "advisory"` with every dimension in `unbounded`, and a bare `bun test` exited 1 with `RESOURCE_LIMIT_REQUIRED` on the runner. Nothing stops a process that is over the ceiling; the ceiling refuses the NEXT session. Task coalitions are the one right shaped object and are closed: creation is gated on `task_is_in_privileged_coalition()`, spawning into one needs a private Apple entitlement, and `coalition_ledger()` is root only and caps disk writes |
| Process group reuse | Limited | A pgid is reused, so a sweep on a remembered number could reach the person's own processes. The supervisor records the leader's start time and executable at creation, and `groupIsStillOurs()` checks both before every sweep. `tests/macos.test.ts` was shown to REFUSE a correct pgid with a start time an hour off, and one with the wrong executable |
| Private storage and per user paths | Limited | Socket, state and connector under `~/Library/Application Support/sbar-orbit`, workspaces under `~/Library/Caches`, agent in `~/Library/LaunchAgents`. None is TCC gated. The socket path length is asserted against Darwin's 104 byte `sun_path`, because a longer path binds elsewhere in silence rather than failing |
| Autostart | Limited, and narrower than Linux | A LaunchAgent starts the broker at LOGIN. There is no analogue of `loginctl enable-linger`: `launchAgentStatus()` reports `startsAtBoot: false` rather than omitting the question |
| Not raising a Keychain dialog | Limited, measured on two runners, and the dialog itself still unobserved | The reasoning stands and is now backed by a measurement on macOS 26.6.2 arm64 and 15.7.9 x64. `keychain_password_mac.mm` looks the key up by compile time constants, so a fresh `--user-data-dir` reuses the person's `Chrome Safe Storage` item and a binary off its ACL raises a modal dialog; Orbit passes `--use-mock-keychain`, documented in `os_crypt_switches.h` as existing to prevent blocking dialogs, plus `--password-store=basic`. What two Macs added: both switches reach the browser process the kernel reports, 2 of a 10 to 11 process tree with no process carrying a contradicting store; an Orbit launch creates no `Chrome Safe Storage` item; and the negative control lands on both hosts, since stripping the two switches makes the very next headless launch create one in `login.keychain-db`, attributes and all, while still publishing a CDP endpoint. An item planted with an empty ACL blocked an off ACL read for a full 20 second budget on both hosts, so the hazard is real there rather than hypothetical. **That no modal appears on a person's real account remains unobserved**: a runner has no window server session to draw one on, and its keychain is not a person's, so `SecItemCopyMatching` returns `errSecInteractionNotAllowed` rather than waiting on anyone. A throwaway account on a real Mac with a real Chrome history is what would close it. See [the fragment](fragments/macos-keychain.md), runs 35434329486 and 35434498535 |
| Resource accounting, probe | Limited | `proc_pid_rusage` reachable from `bun:ffi` with no helper; `ri_phys_footprint` 88.9 MiB against `ps` 115.4 MiB. G24 |
| Session job, `launchctl`, probe | Limited | `bootstrap gui/501` accepted a job in a real gui session and `bootout` left no survivors of its group. A Keystone agent was not present to test. G25 |
| Profile clone on APFS, probe | Limited | `cp -c` shared blocks with no growth in used space, `cp -Rpc` returned 0. G22 |
| Real sessions, profile clone | **Refused** | Three independent reasons, any one sufficient: the cookie key is a Keychain item whose ACL is bound to Chrome's code signature and reading it raises a dialog on the person's screen; TCC grants follow the code signature and the bundle identifier rather than the profile, so a clone would inherit their camera, microphone, Screen Recording and file access along with their cookies; and the clone writes into the shared `com.google.Chrome` defaults domain. The APFS clone primitive works, which is why this refusal is stated in its own branch: the mechanism being available is not a reason to use it |
| Reading `Chrome Safe Storage` from any helper binary | **Refused** | Chromium's own design document states macOS raises a dialog when a different application requests the item, and that dialog takes focus on the person's screen |
| The private display, native applications | **Refused** | No second concurrent GUI session for one user, and acting in place drives the person's own windows |
| A second Aqua session for an already logged in user | **Refused** | No documented Apple API creates one. Fast User Switching gives a different user a different Keychain |
| Screen Recording, Accessibility, Input Monitoring, Automation | **Refused** | Each is a dialog, and each of the four is a route Orbit does not need. `scripts/public-audit.ts` fails the build on the symbols |
| Spawning `/usr/bin/python3` on darwin | **Refused** | That path is a stub that raises the Command Line Tools installer as a window on the person's screen. `bin/sbar-orbit` refuses its Python subcommands there by name rather than letting the path be reached |
| Downloading a browser or a helper | **Refused** | First launch of a quarantined binary prompts |
| Any macOS version below 13 | **Refused** | TCC behaviour there is unmodelled, so it is refused rather than reasoned |
| Origin lease below the browser | Reasoned, with no equivalent designed | No network namespaces. `pf` is system wide and root only, and a per process filter means a Network Extension, which means an entitlement and a signed installer. G30 |

## Which report to file

| What you have | Where it goes | What it must carry |
|---|---|---|
| A `Measured` row that did not hold on a Fedora 44 wlroots host | Bug report | `sbar-orbit doctor --report`, the command you ran, and what happened instead |
| A `Reasoned` row that you tried on your own host class | Platform test report | The same report, plus which gate you closed or failed, and the output you read it from |
| A `Refused` row | Nowhere | The refusal carries a primary source in this file. If you believe that source is wrong, the report is about the source, not about Orbit |
| A `Failed` row | Nowhere new | It is already recorded. A second data point on the same failure is welcome as a platform test report |

A platform test report that closes a gate moves a row from `Reasoned` to `Measured, 1 host, issue #N`
in this file, with the date and the Orbit version it was run against. Nothing moves without that.
