# Disposable Codex composer readiness

This probe used a copied Desktop ASAR, a fake ChatGPT account, a fake saved Codex thread, and Orbit's private display. The installed Desktop and the person's profile were not changed. All new Desktop behavior is gated by `isCodexLinuxAttachFixtureWriteReady()` and remains unavailable in the public attach path.

## Measured sequence

1. The original copied UI showed `App-server task is not ready: execution-config-loading` on submit. The fake account's Statsig bootstrap had failed with `Workspace routing is unavailable`. A fixture-only `readPermissionRefreshEnabled()` override alone had not removed the error.
2. A new fixture-only execution settings fallback returned bounded defaults instead of waiting for unavailable Statsig assignments. In the first new UI run, the submit advanced to `Failed to load local configuration for composer submit`. Its `config/read` RPC was denied by the gate. There was no UI `turn/start`. Evidence: `/var/tmp/codex-private-smoke-write-v/orbit-client-stderr.log.before-composer-config` and `/var/tmp/codex-private-smoke-write-v/gate-audit-first.jsonl.before-composer-config`.
3. Static inspection found the queued composer preparation awaiting exactly three reads: `config/read` with `includeLayers:true` and the current cwd, `configRequirements/read`, and paginated `permissionProfile/list`. A second fixture-only Desktop patch populated those local caches with an empty config, null requirements, and an empty profile list. It did not forward these requests or alter the normal Desktop path. The focused unit tests checked the synthetic results and unchanged normal RPC behavior.
4. In the second new UI run, the local-config error disappeared. Submit then requested `thread/resume` at critical priority from `thread_hydration`. The gate denied it with `-32601`, and the client logged `thread_resume_failed`. The UI's typed text remained in the composer. The gate audit recorded zero UI `turn/start`, and the fake owner's latest rollout did not contain `Orbit private saved-thread follow-up`. Evidence: `/var/tmp/codex-private-smoke-write-v/orbit-client-stderr.log` lines 393 and 394, `/var/tmp/codex-private-smoke-write-v/gate-audit-first.jsonl`, `/var/tmp/codex-private-smoke-write-v/orbit-client-after-write-first.jpg`, and `/var/tmp/codex-private-smoke-write-v/owner-codex-orbit-2de934b5/sessions/2026/09/29/rollout-2026-09-29T06-18-15-01a0eaf4-a196-7e91-b8d2-96ca5c8a1611.jsonl`.

The current copied Desktop source assembles `thread/resume` from the thread ID, saved path, model and provider, cwd, and conditional settings, permissions, and paginated page options. This is a source-level shape, since this gate audit records method names and outcomes, not request fields. A separate cold-resume experiment measured writes to the owner's saved history and SQLite state, so this probe did not permit raw `thread/resume`.

Focused Desktop tests passed: five tests, zero failures with `bun test ./linux-features/shared-app-server-socket/test.js --test-name-pattern 'fixture-only|attach-only viewer patch'`. Both disposable UI runs completed and stopped their fake processes. The UI has still not submitted a saved turn. This does not measure a personal account or the ability to use every Codex action and tool.
