# Inherited descriptor controls for the experimental socket launcher

Measured on 30 September 2026. This closes startup descriptor inheritance in
`seccomp-wayland-app-probe.c`, not every socket or file authority route.

## Reproduced before changing the launcher

The test launcher deliberately passed a connected fixture socket through exec.
No personal socket, account, file or terminal was used.

| Entry route | Original behavior |
| --- | --- |
| Connected socket on FD 19, private pair support disabled | Application wrote all 14 generated bytes directly to the foreign server, with zero approved broker connections |
| Connected socket on FD 19, private pair support enabled | Existing `close_range` rejected the write with EBADF |
| Named connected socket on standard input | Application read the generated `fixture-input` payload without a broker connection |
| Generated PTY on standard input | Application inherited a usable terminal |

The PTY control initially lost its master during exec and therefore failed to
model a live terminal. Keeping a duplicate master open in the fixture launcher
corrected the harness before the successful unfixed reproduction. No personal
terminal was opened.

## Change

Before opening any pinned endpoint or handoff descriptor, the broker now:

1. Validates descriptors 0, 1 and 2.
2. Accepts regular files, FIFOs and `/dev/null`.
3. Accepts anonymous UNIX STREAM socket pairs only when both socket addresses
   are unnamed and SO_PEERCRED identifies the immediate launcher PID, UID and GID.
4. Rejects other sockets, terminals, devices and unavailable standard descriptors.
5. Closes every descriptor above 2 with `close_range` in the broker itself.

The eventual application also closes every descriptor above 2 after listener
handoff, unconditionally. Private pair support no longer controls this cleanup.
Closing extra descriptors in the broker prevents it from retaining the
fixture socket after the target drops its copy. Deliberate standard IO authority
is retained.

An initial blanket rejection of socket stdio rejected Bun's normal transport.
The anonymous-parent-channel rule preserves that legitimate launcher channel
without admitting the named foreign socket fixture. No CONTINUE response,
inspected child pointer or numeric application-FD exception was added.
Unsupported `close_range` or unsafe standard descriptors cause exit status 2
before application exec. There is no permissive fallback.

## Results after the change

- Both FD 19 cases returned EBADF and delivered zero bytes to the foreign server.
- Named socket and PTY standard-input cases returned status 2, with no application
  result file, proving the fixture application did not execute.
- Existing pair controls passed, including delegated private pairs, STREAM and
  SEQPACKET messages, rejected device/foreign socket rights, FD reuse, size/flag
  limits and the 128-pair registry bound.
- Existing TCP controls passed: two selected connections, zero blocked-port
  accepts, copied data, rejected TCP rights and address/port/UDP controls.
- Installed Loupe still displayed the generated two-color image on the owned
  Orbit display. Both measured pixel colors matched. Application exit was 0,
  brokerFailure was 0 and forcedStop was false. This used private bus credentials,
  loopback discovery and private pairs.
- `bun run typecheck`, compiler warnings-as-errors and `git diff --check` passed.

The inherited-descriptor harness destroys its owned server sockets before
closing the listeners. A callback stall in an intermediate run was diagnosed
with the still-live harness handle; its broker children had already exited.
Only those identified harness processes were stopped and their owned temporary
roots removed. The final run exited 0 and removed both temporary roots.


`ORBIT_INHERITED_EXPECT_UNFIXED=1` selects the original-leak oracle for use with
unfixed code. It is not a flag that disables the fix. The successful reproduction
was recorded before modifying the launcher. After the fix the normal oracle
must pass, and the original-leak oracle must reject the corrected behavior.

## Limits beside the result

The named standard-input socket and generated standard-input PTY were tested.
The source applies the same gate to stdout and stderr, but those rejection cases
were not separately exercised. Parent-channel substitution races, PID namespace
changes, launcher-parent exit, FIFO peer authority and regular-file selection
are not established by this test. The immediate parent remains a trusted
provider of standard IO, which retains deliberate file or pipe authority.

This does not mediate later `accept`, descriptor receipt, `/proc` access,
`pidfd_getfd`, ptrace or arbitrary file and device authority. Broker-created pair
injection remains non-atomic. The broker's credential differences and other
transport limits remain. The launcher is still experimental and is not linked
into Orbit's production application action. Current-account Nextcloud was not
rerun for this change. No full-suite result or complete sandbox is claimed.
